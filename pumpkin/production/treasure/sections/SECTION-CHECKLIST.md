# One-section scene checklist

- Define exact bounds, seams, gameplay job and a one-sentence story. Name the best visual reference.
- Inspect current scene, licences, reusable kits and working gameplay contracts. Capture source/place hashes; back up the rbxl before Rojo.
- Lock arrival and overview cameras. Render BEFORE before drafting props. Check what actually blocks the eye.
- Make a small crop board and one target concept. State which parts are aspirational or outside section scope.
- List each prop and its job. Work large silhouette → purposeful clusters → small accents. Delete filler.
- Preserve lane geometry, floor/query tags, routes, drop rules and gameplay sources. Reserve clear player corridors. If using apron-border artwork, document its exact exception and prove all actual route envelopes stay clear.
- Test support across the whole footprint; use actual mesh base bounds. Check feet, rail/post joints, lamp brackets, bed corners, roots, clipping and grade breaks from player height.
- Keep colours/materials consistent. Reserve cyan/gold for portal/reward; avoid equal-brightness clutter.
- Export the actual builder and source meshes. Use identical cameras and lighting for before/after. Label offline effect proxies and missing runtime evidence.
- Get a blind critic against REFS; fix the worst gap. Repeat once. Keep the two review images and a short change record.
- Compile mounted scripts; compare serialized world and rebuilt collision/floor/tag signatures; verify kit manifest keys. Run appropriate existing checks.
- Run all eight StudioPassAll suites with the owner account and mock persistence when Studio is available. Save actual results and screenshots; never inherit an earlier green result.
- Make SBS.jpg beside target; inspect it at normal and phone size. Record 1–3 When/Do/Because lessons, remaining gaps and what Zion must review.
- Deliver ONE scene. No commit, publish, other-section expansion or money spent without authorization.
