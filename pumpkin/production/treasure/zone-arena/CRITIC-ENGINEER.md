## Critical blockers common to all three

1. **One active arena/cargo is structural, not a map setting.** CHECKED: Greybox.server.luau:28-35 creates one rules object and arena; :238-246 publishes one world EscapeDeadline/ItemId and one pair of prompts; :806-823 builds one nest; :1204 invalidates holds against rules.active; :1249-1254 refills and recovers that single active item. INFERRED correction: define authoritative cargo records indexed by immutable item ID and active zone slot, explicit zone/guardian ownership, item-scoped prompt/hold/version checks, and independent refill/deadline events. Keep actor carry capacity at one. HUD deadline must be actor/item scoped. Do not duplicate the existing singleton loop fifteen times.

2. **Safe banking must remain one durable transition across all concurrent cargo.** CHECKED: Greybox.server.luau:550-574 sets securePending before yielding, reconciles the same pending ID, then calls Rules.secure; Profiles.luau:41-80 retains one pending operation/revision until OnAfterSave acknowledgment; :82-98 serializes profile mutations. Domain.luau:92-110 deduplicates against pending and current pets. INFERRED correction: retain these acknowledgment and locking semantics; add zone-bank progress in the same transaction as the award. Once pet replacement exists, checking only current pets is insufficient as a permanent consumed-ID ledger: retain durable award receipts or another durable monotonic identity proof so a removed pet's old ID cannot be awarded again. Safe pending cargo must be protected from timeout/handoff/refill while the save resolves. Prove disconnect and retry behavior before multiplying zones.

3. **Eight pets currently ends progression.** CHECKED: Config.luau:8 sets MaxPets=8; Domain.secure and Domain.open reject full plots; Service.luau:63-68 prevents entry at capacity; Greybox.server.luau:860 also rejects a full pen. INFERRED correction: specify replacement choice and one acknowledged transaction that removes the selected pet and installs the new award without exceeding eight. Handle RAM visuals, pending cargo, save uncertainty and replay IDs together. Merely raising capacity or removing canEnter leaves other blockers.

4. **The proposed economy and purchase gates do not exist in this schema.** CHECKED: Domain.luau:16-30 stores version 1, Meadow unlock, pets and a single pending award; :31-76 validates that schema; :108 stores only ID/tier/placed; :136-142 sums rarity rates without zone multipliers. Service.secure passes ID/tier/flags only. Profiles.load validates existing data without an existing-envelope version migration step. Greybox.server.luau:1150-1151 overwrites speed from global constants each update. INFERRED correction: migrate existing version-1 profiles before validation; store validated zone identity on pending awards and pets, durable prior-zone bank progress, permit ownership and ordered boots ranks. Perform purchases and progress writes on the server through acknowledged transactions. Preserve old earnings explicitly, and derive both published pet income and actual ticks from the same rate calculation. Walking stays ungated; only steal checks permit. Route timing must be evaluated with purchased speed, not zone auto-scaling.

5. **Threat caps and foreign-cargo immunity need a shared scheduler.** CHECKED: RaidSlice.luau:202-260 coordinates raid versus Keeper through one arena's attack/tunnel/decoy flags, and :187/:233 records only the last raid item on that arena. KeeperAttacks.choose/step iterates supplied actors, and step's hit acceptance checks Run/safe/sight rather than cargo-zone ownership. Arena.dashLegal uses a camp-radius leash, not the proposed section-plus-one boundary. INFERRED correction: introduce global awake-Keeper/runner budgets and per-actor dangerous-commitment reservations, including collateral hits and overlapping area effects. Local attack flags cannot enforce shared caps. Filter legal targets and hits by explicit ownership; keep per-cargo raid-used state on cargo lifetime records so A/B/A handoffs cannot reopen A's raid. Skip deployment when no budget; never create a queue. Keep existing warning acknowledgment semantics and baseline tells.

Gameplay.luau hardcodes one protected rectangle, nest/camp/portal and Meadow route families. Outsmart.luau uses absolute local bait/bell coordinates and tags a specifically named boulder. RaidSlice.luau:26-36 has two axis-aligned authored encounters; its arrows/vault logic assumes particular axes. INFERRED correction: reusable zone-local transforms and authored floor, cover, bypass, recovery and safe-line definitions must be the source of truth. Do not retain invisible old island collision or transplant whole Meadow models. X needs simplest rectangular regions; Y needs turn/divider/landing checks; Z needs radial/spoke boundary and junction checks. ## Lessons

- When a design adds concurrent loot, refactor identity and durable transitions first, because singleton prompts and save retries cross-cut the map.
- When inventory replacement removes old rewards, retain award receipts, because current inventory membership no longer proves an ID was already consumed.
- When phone risk depends on replicated effects and queries, measure a crowded scene, because map footprint alone does not predict cost.
