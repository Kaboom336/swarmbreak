It must already use the intended registry, one economy authority, bank-only award, retained cargo identity/deadline, full-capacity replacement path and actor-scoped threat/UI state. ## Lessons

- When scaling one encounter into zones, refactor ownership and identity first, because duplicated presentation can conceal singleton state.
- When adding reward progression, persist the award's earning basis, because rarity alone cannot reconstruct zone value.
- When permitting full-capacity replacement, change entry, secure and open together, because a final dialog cannot bypass earlier authority checks.
