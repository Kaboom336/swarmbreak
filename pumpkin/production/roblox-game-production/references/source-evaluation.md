# Source evaluation

## Find the right shoulders to stand on

Search in this order as appropriate: existing project modules, Roblox official samples, licensed source repositories, creator-hosted raw art/audio packs, then other marketplaces allowed by the user's budget. Videos supply interaction and presentation references, not reusable code or asset rights.

For each candidate record: canonical URL, author, checked date, exact license, free/paid tier, downloadable source, platform dependencies, what is inspected, what is tested, and which concrete production problem it solves. A README saying "production-ready" or "mobile compatible" is an unverified claim until demonstrated. MIT code still requires the license notice; DRM-free does not mean open source. Check code and art permissions independently.

Judge foundations on core-loop fit, social topology, readable source, server authority, saving/migration, device controls, maintenance burden, art replacement cost, and ability to remove irrelevant monetization. Missing license or incompatible import restrictions can disqualify an otherwise attractive candidate. A modular donor can be useful even when its entire game is unsuitable.

Do not claim a successful game's original template exists merely because a seller offers a similarly named clone. Do not assume player counts, a popular video, or a feature list establish code quality.

## Capture evidence from references

Record the first action, time to first response/reward, camera framing, object scale, motion beats, social interaction, upgrade reveal, and return route. For videos include URL, timestamp, and the visible observation. Separate creator descriptions from watched footage and inference. If footage is unavailable, mark that gap and continue with another accessible source; never invent having watched it.

## Asset intake

Prefer raw mesh/image/audio files when a project forbids scripted Store items. Review archives before import, retain license/source records, and import only selected files. A model listing showing MeshParts alone is not a complete descendant inspection. For a no-script Store policy, reject unknown or script-bearing items before insertion; inserting then deleting scripts does not satisfy that policy. Official sample source can be studied independently without inserting Store models.

Normalize scale, pivots, naming, atlas/material use, collision and texture resolution. Decorative meshes should use simpler collision and restrained shadows. Check in-engine at gameplay distance and on a phone-shaped viewport. Record uploaded asset IDs and permissions; local CC0 files do not automatically supply usable Roblox IDs.

Use one coherent environment vocabulary. Budget separately for the focal object, states, animation, UI symbols, VFX sprites, sound cues, and thumbnail/trailer renders. Kits save modelling time; they do not make a composed scene or a signature character automatically.
